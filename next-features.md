## v2.0 — Backend & Multi-Device Sync

### Why a Backend?

Right now all data lives on-device. Moving to a backend enables:
- Access entries from any device
- Employer visibility into employee hours
- Automatic backups
- Team management

### Chosen Stack: Supabase + PostgreSQL

Supabase is an open-source Firebase alternative built on top of **real PostgreSQL**. It provides everything needed without vendor lock-in.

| Layer | Technology | Why |
|---|---|---|
| Database | PostgreSQL (via Supabase) | Full SQL — ideal for payroll reports, date range queries, GROUP BY |
| Auth | Supabase Auth | Email, Google, Apple sign-in built-in |
| Real-time | Supabase Realtime | WebSocket subscriptions — live employer dashboard |
| REST API | Auto-generated by Supabase | No custom API server needed |
| Row-level Security | PostgreSQL RLS policies | Employees see only their own data |
| Employer Web App | Next.js on Vercel | Server-side rendering, free hosting |

### Cost

## PostgreSQL Schema

```sql
-- Companies
create table companies (
  id          uuid primary key default gen_random_uuid(),
  name        text not null,
  invite_code text unique not null,   -- 6-digit code for employees to join
  created_at  timestamptz default now()
);

-- Users (extends Supabase auth.users)
create table profiles (
  id          uuid primary key references auth.users,
  company_id  uuid references companies,
  name        text,
  email       text,
  role        text check (role in ('employee', 'admin')) default 'employee',
  joined_at   timestamptz default now()
);

-- Projects / Jobs
create table projects (
  id          uuid primary key default gen_random_uuid(),
  company_id  uuid references companies,
  name        text not null,
  client      text,
  hourly_rate numeric(10,2),
  billable    boolean default true,
  color       text,
  created_by  uuid references profiles
);

-- Time Entries
create table time_entries (
  id             uuid primary key default gen_random_uuid(),
  employee_id    uuid references profiles,
  company_id     uuid references companies,
  project_id     uuid references projects,
  start_time     timestamptz not null,
  end_time       timestamptz,           -- null = currently running
  pause_minutes  integer default 0,
  notes          text,
  billable       boolean default true,
  approved       boolean default false, -- employer approval
  created_at     timestamptz default now()
);
```

### Row-Level Security (RLS) Policies

```sql
-- Employees can only read/write their own entries
create policy "own entries" on time_entries
  using (employee_id = auth.uid());

-- Admins can read all entries in their company
create policy "admin read all" on time_entries
  using (
    exists (
      select 1 from profiles
      where id = auth.uid()
      and company_id = time_entries.company_id
      and role = 'admin'
    )
  );
```

## Migration Plan (Employee App → Supabase)

The current Zustand store maps cleanly to the PostgreSQL schema — migration is additive.

| Step | What changes |
|---|---|
| **1. Add Auth** | New login/signup screen before tabs. Store session in settings store |
| **2. Company Join** | Onboarding: create company or enter 6-digit invite code |
| **3. Sync Writes** | Replace AsyncStorage writes with Supabase inserts in store actions |
| **4. Real-time reads** | `supabase.from('time_entries').on('*', cb).subscribe()` replaces hydration |
| **5. Offline** | Keep Zustand + AsyncStorage as local cache; sync on reconnect |

The app remains **offline-first** — local state is the source of truth, Supabase is synced in the background.
